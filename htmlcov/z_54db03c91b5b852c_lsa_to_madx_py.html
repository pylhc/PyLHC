1""" 

2LSA to MAD-X 

3------------ 

4 

5This script is meant to convert various ``LSA`` knobs to their ``MAD-X`` equivalent scripts. 

6 

7.. code-block:: none 

8 

9 usage: lsa_to_madx.py [-h] --optics OPTICS [--knobs [KNOBS ...]] [--file FILE] 

10 

11 LSA Knob to MAD-X Converter.This script can be given an LSA LHC optics, a list 

12 of LSA knobs or a file with LSA knobs and will, for each knob, retrieve the 

13 affected LHC power circuits and determine the corresponding MAD-X variables 

14 changes. It will then output both definition files and MAD-X scripts reproducing 

15 the provided knobs. 

16 

17 options: 

18 -h, --help show this help message and exit 

19 --optics OPTICS The LSA name of the optics for which the knobs are defined. 

20 --knobs [KNOBS ...] The full LSA names of any knob to convert to their MAD-X equivalent. 

21 --file FILE Name of a file with knob names and strength factors to use. A 

22 single knob should be written per line, and lines starting with a 

23 '#' character will be ignored. 

24 

25One can simply want to find out the ``MAD-X`` way to reproduce a given knob. 

26For instance, to find reproduce ``LHCBEAM/MD_ATS_2022_05_04_B1_RigidWaitsShift_IP1pos``, which is defined in the ``R2022a_A30cmC30cmA10mL200cm`` optics one would run: 

27 

28.. code-block:: none 

29 

30 python -m pylhc.lsa_to_madx \\ 

31 --optics R2022a_A30cmC30cmA10mL200cm \\ 

32 --knobs LHCBEAM/MD_ATS_2022_05_04_B1_RigidWaitsShift_IP1pos 

33 

34Two files, **LHCBEAM_MD_ATS_2022_05_04_B1_RigidWaitsShift_IP1pos_definition.tfs** and **LHCBEAM_MD_ATS_2022_05_04_B1_RigidWaitsShift_IP1pos_knob.madx** will be written to disk. 

35 

36.. warning:: 

37 In ``MAD-X``, variable names with 48 or more characters will cause an issue. 

38 As a consequence, this script will automatically truncate the knob name if needed when created the trim variable name. 

39 One should not be surprised if long ``LSA`` knob names appear slightly differently in the created ``MAD-X`` files, then functionality stays intact. 

40 

41 For instance, the knob ``LHCBEAM/MD_ATS_2022_05_04_B1_RigidWaitsShift_IP1pos`` will lead to the following trim variable definition: 

42 

43 .. code-block:: fortran 

44 

45 trim_D_ATS_2022_05_04_B1_RigidWaitsShift_IP1pos = 1.0; 

46 

47In order to reproduce a specific machine configuration at a given time, one can gather all knobs and their trim values for this configuration in a text file and feed this file to the script. 

48In this file, each line should hold a knob name as it appears in LSA and its trim value. 

49Lines starting with a ``#`` character will be ignored. 

50 

51For instance the following **knobs.txt** file gathers a 2017 LHC configuration: 

52 

53.. code-block:: none 

54 

55 # Nonlinear Corrections 

56 LHCBEAM/2017_IRNL_IR1a4 0.5 

57 LHCBEAM/2017_IRNL_IR1b3_couplFD 1.0 

58 LHCBEAM/2017_IRNL_a3b3_tuneFD 1.0 

59 LHCBEAM/2017_IRNL_b4 1.0 

60 LHCBEAM/2017_NL_IR1_30cm_kcssxr1 1.0 

61 LHCBEAM/2018_IRNL_IR1a3 1.0 

62 LHCBEAM/2018_IRNL_IR1b3 1.0 

63 LHCBEAM/2018_IRNL_IR5a3 1.0 

64 LHCBEAM/IR5_a4_2018 1.0 

65 # Local correctors close to IP 

66 LHCBEAM/2017_ATS_Inj_LocalCoupling 1.0 

67 LHCBEAM/2017_ATS_LocalCorrection 1.0 

68 # Chromatic Coupling 

69 LHCBEAM/chromatic_coupling_b1_40cm_ctpps2_2017_v2 -1.0 

70 LHCBEAM/chromatic_coupling_b2_40cm_ctpps2_2017 -1.0 

71 # Beta-beat 

72 LHCBEAM/b1_global_beta_beating_40cm_ctpps_2017_v2 1.0 

73 LHCBEAM/b2_global_beta_beating_40cm_ctpps_2017 1.0 

74 LHCBEAM/2017_beam1_beta_CrossingAngleCompensation 1.0 

75 LHCBEAM/2017_30cm_GlobalCorr_wXing_Beam2_v2 1.0 

76 LHCBEAM/B2_2017_global_correction_Xing 1.0 

77 # Total Phase advance 

78 LHCBEAM/2017_B2_MQT_total_phase_correction 1.0 

79 LHCBEAM/B1_2017_MQT_total_phase_correction 1.0 

80 # Arc-by-arc coupling 

81 LHCBEAM/global_coup_knob_all_correctors -1.0 

82 

83One can provide this file with the corresponding optics and get a ``MAD-X`` file for each defined knob with the appropriate trim value. 

84In this case many files will be created. 

85The call would be: 

86 

87.. code-block:: bash 

88 

89 python -m pylhc.lsa_to_madx \\ 

90 --optics R2017aT_A30C30A10mL300_CTPPS2 \\ 

91 --file knobs.txt 

92 

93Hint: the knobs active at a given time can be retrieved with the `~pylhc.machine_settings_info` script.

115def parse_knobs_and_trim_values_from_file(knobs_file: Path) -> dict[str, float]: 

116 """ 

117 Parses a file for LSA knobs and their trim values. Each line should be a knob name 

118 following by a number of the trim value. If no value is written, it defaults 

119 to ``1.0``. Lines starting with a ``#`` are ignored. 

120 

121 Args: 

122 knobs_file (~pathlib.Path): Path to the file with definitions. 

123 

124 Returns: 

125 A `dict` with as keys the parsed knob names and as values their associated trims. 

126 """ 

127 knob_lines = [ 

128 line for line in Path(knobs_file).read_text().splitlines() if not line.startswith("#") 

129 ] 

130 results = {} 

131 

132 for line in knob_lines: 

133 knob = line.split()[0] # this is the knob name 

134 try: # catch the trim value, which is a number after the knob name 

135 trim = float(line.split()[1]) 

136 results[knob] = trim 

137 except IndexError: # there is no number, we default the trim value to 1.0 

138 LOG.debug(f"No trim value was specified for knob '{knob}' - defaulting to 1.0") 

139 results[knob] = 1.0 

140 return results

143def get_sign_madx_vs_lsa(madx_name: str) -> int: 

144 """ 

145 Return the sign convention between madx and lsa for the given variable. 

146 

147 Args: 

148 madx_name (str): Name of the variable as used in MAD-X. 

149 

150 Returns: 

151 int: 1 or -1. 

152 

153 """ 

154 # Test for skewness: 

155 match = re.match(r"^.c?[qsodt]s", madx_name) # k, then maybe a "c", then type, then skew 

156 if match is not None: 

157 LOG.debug(f"{madx_name} belongs to a skew magnet: Sign is inverted betwen LSA and MAD-X") 

158 return -1 

159 

160 # Test for Q2 

161 if madx_name.lower().startswith("ktqx2"): 

162 LOG.debug(f"{madx_name} belongs to Q2: Sign convention is unknown") 

163 raise NotImplementedError( 

164 "Q2 is not implemented yet, as the sign convention LSA-MADX is not known. " 

165 "Please check and implement." 

166 ) 

167 

168 LOG.debug(f"Sign of {madx_name} is the same in LSA and MAD-X.") 

169 return 1

172def get_madx_script_from_definition_dataframe( 

173 deltas_df: tfs.TfsDataFrame, 

174 lsa_knob: str, 

175 trim: float = 1.0, 

176 by_reference: bool = True, 

177 verbose: bool = False, 

178) -> str: 

179 """ 

180 Given the extracted definition dataframe of an LSA knob - as returned by 

181 `~pylhc.data_extract.lsa.LSAClient.get_knob_circuits` - this function will generate the 

182 corresponding ``MAD-X`` text commands that would reproduce this knob in a script. 

183 

184 Args: 

185 deltas_df (~tfs.frame.TfsDataFrame): The extracted definition dataframe of an ``LSA`` knob. This 

186 can be obtained with `~pylhc.data_extract.lsa.LSAClient.get_knob_circuits`. 

187 lsa_knob (str): The complete ``LSA`` name of the knob, including any ``LHCBEAM[12]?/`` part. 

188 trim (float): The trim value to write for the knob. Defaults to 1. 

189 by_reference (bool): If true, creates an _init variable and uses deferred expressions (`:=`) 

190 so that changing the trim later in the script changes all 

191 variables as well. Might be problematic if a variable depends on 

192 multiple trim-knobs. 

193 Otherwise `variable = variable + delta*trim` is used. 

194 verbose (bool): Adds some extra comments into the madx code. 

195 

196 Returns: 

197 The complete ``MAD-X`` script to reproduce the knob, as a string. 

198 """ 

199 LOG.debug(f"Determining MAD-X commands to reproduce knob '{lsa_knob}'") 

200 change_commands = [f"! Start of change commands for knob: {lsa_knob}"] 

201 

202 # Set this to 1 by default but can be changed by the user to reproduce a given trim 

203 trim_variable = _get_trim_variable(lsa_knob) 

204 if verbose: 

205 change_commands.append("! Change this value to reproduce a different trim") 

206 change_commands.append("! Beware some knobs are not so linear in their trims") 

207 change_commands.append(f"{trim_variable} = {trim};") 

208 change_commands.append("! Impacted variables:") 

209 

210 deltas = _get_delta(deltas_df) 

211 

212 # write all inits first (looks nicer in madx) 

213 if by_reference: 

214 for variable in deltas.keys(): # noqa: SIM118 (this is not a dict) 

215 variable_init = f"{variable}_init" 

216 change_commands.append(f"{variable_init:<17} = {variable};") 

217 

218 # write knob-definition 

219 for variable, delta in deltas.items(): 

220 delta = get_sign_madx_vs_lsa(variable) * delta 

221 # Parenthesis around the delta below are important for MAD-X to not 

222 # mess up parsing of "var = var + -value" if delta_k is negative 

223 if by_reference: 

224 variable_init = f"{variable}_init" 

225 change_commands.append( 

226 f"{variable:<12} := {variable_init:^19} + ({delta:^25}) * {trim_variable};" 

227 ) 

228 else: 

229 change_commands.append( 

230 f"{variable:<12} = {variable:^15} + ({delta:^25}) * {trim_variable};" 

231 ) 

232 

233 change_commands.append(f"! End of change commands for knob: {lsa_knob}\n") 

234 return "\n".join(change_commands)

237def _get_trim_variable(lsa_knob: str) -> str: 

238 """ 

239 Generates the ``MAD-X`` trim variable name from an ``LSA`` knob. 

240 Handles the variable name character limit of ``MAD-X``. 

241 """ 

242 # Handle the LHCBEAM-Part: 

243 lhcbeam = re.match(r"^LHCBEAM(\d?)", lsa_knob.upper()) 

244 if lhcbeam is not None: 

245 madx_knob = lsa_knob.split("/")[-1] # without the LHCBEAM[12]?/ part 

246 if lhcbeam.group(1): 

247 # beam has a number: there might be two knobs with this name 

248 madx_knob = f"B{lhcbeam.group(1)}_{madx_knob}" 

249 else: 

250 madx_knob = lsa_knob 

251 

252 # Clean up the name 

253 madx_knob = madx_knob.replace("-", "_").replace("/", "_") 

254 for c in set(madx_knob): 

255 if c not in ALLOWED_IN_MADX_NAMES: 

256 LOG.debug(f"Knob contains the character '{c}', which is not allowed in madx. Removing.") 

257 madx_knob = madx_knob.replace(c, "") 

258 

259 # MAD-X will crash if the variable name is >48 characters or longer! It will also silently fail 

260 # if the variable name starts with an underscore or a digit. Adding "trim_" at the start circumvents 

261 # the latter two, and we make sure to truncate the knob so that the result is <=47 characters 

262 if len(madx_knob) > 42: 

263 madx_knob = madx_knob[-42:] 

264 LOG.debug(f"Truncated knob name to '{madx_knob}'.") 

265 

266 trim_variable = f"trim_{madx_knob.lstrip('_')}" 

267 LOG.debug(f"Converted knob-name '{lsa_knob}' to trim variable '{trim_variable}'.") 

268 return trim_variable

271def _get_delta(deltas_df: tfs.TfsDataFrame) -> pd.Series: 

272 """Get the correct delta-column""" 

273 if "DELTA_K" not in deltas_df.columns: 

274 LOG.debug("Using DELTA_KL column.") 

275 return deltas_df.DELTA_KL 

276 

277 if "DELTA_KL" not in deltas_df.columns: 

278 LOG.debug("Using DELTA_K column.") 

279 return deltas_df.DELTA_K 

280 

281 if (deltas_df.DELTA_K.astype(bool) & deltas_df.DELTA_KL.astype(bool)).any(): 

282 raise ValueError( 

283 "Some entries of DELTA_KL and DELTA_K seem to both be given. " 

284 "This looks like a bug. Please investigate." 

285 ) 

286 

287 LOG.debug("Both DELTA_K and DELTA_KL columns present, merging columns.") 

288 return pd.Series( 

289 np.where(deltas_df.DELTA_K.astype(bool), deltas_df.DELTA_K, deltas_df.DELTA_KL), 

290 index=deltas_df.index, 

291 )

298 """Parse Commandline Arguments."""

308 dest="optics", 

309 type=str,

313 parser.add_argument( 

314 "--knobs", 

315 dest="knobs", 

316 type=str, 

317 nargs="*", 

318 required=False, 

319 help="The full LSA names of any knob to convert to their MAD-X equivalent.",

333def main(): 

334 options = _get_args() 

335 lsa_optics = options.optics 

336 

337 if not options.knobs and not options.file: 

338 LOG.error("Need to provide either a list of knob names or a file with 1 knob name per line") 

339 exit(1) 

340 

341 if options.knobs and options.file: 

342 LOG.error("Either provide knobs at the command line or from a text file, but not both") 

343 exit(1) 

344 

345 if options.file and Path(options.file).is_file(): 

346 LOG.info(f"Loading knob names from file '{options.file}'") 

347 knobs_dict = parse_knobs_and_trim_values_from_file(Path(options.file)) 

348 else: # given at the command line with --knobs, we initialise trim values to 1 

349 knobs_dict = dict.fromkeys(options.knobs, 1.0) 

350 

351 LOG.info("Instantiating LSA client") 

352 lsa_client = LSAClient() 

353 unfound_knobs = [] 

354 

355 with timeit(lambda elapsed: LOG.info(f"Processed all given knobs in {elapsed:.2f}s")): 

356 for lsa_knob, trim_value in knobs_dict.items(): 

357 LOG.info(f"Processing LSA knob '{lsa_knob}'") 

358 try: # next line might raise if knob not defined for the given optics 

359 knob_definition = lsa_client.get_knob_circuits( 

360 knob_name=lsa_knob, optics=lsa_optics 

361 ) 

362 madx_commands_string = get_madx_script_from_definition_dataframe( 

363 deltas_df=knob_definition, lsa_knob=lsa_knob, trim=trim_value 

364 ) 

365 

366 except OSError: # raised by pjlsa if knob not found 

367 LOG.warning( 

368 f"Could not find knob '{lsa_knob}' in the given optics '{lsa_optics}' - skipping" 

369 ) 

370 unfound_knobs.append(lsa_knob) 

371 

372 else: # we've managed to find knobs 

373 # Don't write this in the try block, as it could raise IOError when failing 

374 definition_file = f"{lsa_knob.replace('/', '_')}_definition.tfs" 

375 LOG.debug(f"Writing knob definition TFS file at '{definition_file}'") 

376 tfs.write(definition_file, knob_definition, save_index=True) 

377 

378 madx_file = f"{lsa_knob.replace('/', '_')}_knob.madx" 

379 LOG.debug(f"Writing MAD-X commands to file '{madx_file}'") 

380 Path(madx_file).write_text(madx_commands_string) 

381 

382 if unfound_knobs: 

383 LOG.info( 

384 f"The following knobs could not be found in the '{lsa_optics}' optics: \n\t\t" 

385 + "\n\t\t".join(unfound_knobs) 

386 ) 

387 

388 

389if __name__ == "__main__": 

390 main()
